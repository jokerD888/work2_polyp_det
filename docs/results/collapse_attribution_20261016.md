# 坍塌归因专项诊断报告（2026-10-16）

针对本轮两组实验中出现的三次 ≥20 点瞬态 AP 坍塌（+DCNv4@1924→31.70、Box-Gated@2199→0.57、
Box-Gated@2749→22.69）的专项归因。**未启动任何新训练，未修改任何方法代码**；
仅使用已有产物（checkpoint、metrics.json、训练日志、校准 JSON）+ 每组 3 次复评（每组 ~2 分钟 GPU）。
原始数据：`runs/_launcher/quality-boxgate-a6000-s42/diagnostics/`。

## 1. 评估可靠性：评估异常已排除

- **同一 checkpoint（train/model_best.pth）重复 3 次独立验证 × 2 组 = 6 次复评，与原始 predict
  共 7 份结果全部逐位一致**（AP/AP50/AP75 每一位小数相同；分别在不同 GPU、独立进程执行）。
  证据：`diagnostics/reval_determinism.json`。
- 既有佐证：训练内 eval@5500 与训练后独立 predict 进程对同一权重的输出本就逐位一致。
- 推理路径核实：`SCDAProposalMaskDINO.forward` 在 eval 模式直接走原生 MaskDINO
  （`methods/scda_proposal/model.py:57`），Box-Gated 的门控只作用于训练期辅助监督，
  "推理时收缩框选错"的解释不成立（与审查意见一致）。
- **结论：评估链是确定性的；0.57 反映的是评估那一刻的真实权重/状态，不是评估实现的偶发异常。**

## 2. 训练稳定性：三个坍塌点均伴随真实损失扰动（证据与缺口）

> **日志口径修正（同日晚间）**：经核对 detectron2 源码（`utils/events.py:452-475`），`metrics.json`
> 中带 `smoothing_hint=True` 的标量（含全部损失项）记录的是**过去 ≤20 个 iter 的中位数**，不是该
> iter 的原始值（`JSONWriter` 默认 `window_size=20`）。因此下表的"iter X 损失"应读作"截至 X 的
> 20-iter 窗口中位数"。两点后果：(1) 中位数 ≥2.0 要求窗口内 ≥10 个 iter 同样高——观察到的不是
> 单 batch 毛刺，而是**持续数十 iter 的异常区间**；(2) 2199 行中位数正常不能排除 2180–2199 窗口
> 后半已开始恶化，episode 起点只能限定为 **[~2190, 2200]**，"恰好发生在 2199 那次更新"是仍可能
> 的假设而非测量事实。逐 iter 原始值只有仪表化训练能提供。

20-iter 窗口中位数粒度损失取证（`diagnostics/loss_forensics.json`）：

| 坍塌点 | 评估前损失证据 | 评估后损失证据 |
|---|---|---|
| DCN@1924（31.70） | **iter 1919 ce=1.361、total 72.92**（区域基线 ce≈0.14–0.33、total≈40） | 1939 起回落 |
| Box-Gated@2749（22.69） | **iter 2699–2739 ce=2.608/2.584/2.180**（连续三窗高企） | 2759 起回落 |
| Box-Gated@2199（0.57） | 2099–2199 全部正常（ce≤1.073，无尖峰） | **2219 ce=0.867、2239 ce=1.400（该区域全程最高）** |

- 2199 的形态与 detectron2 的记录时序自洽：iter 2199 记录的损失**先于**该 iter 的参数更新计算完成，
  更新发生在记录之后、评估钩子之前——权重在更新瞬间被扰动，训练随后用 ~200 iter 恢复（2219–2239 损失
  抬升 → 2399 起 normal → 2474 AP 回到 59.14）。
- 三个坍塌区域学习率恒为 4e-4（首次衰减在 4400），排除 LR 事件；`time/data_time` 正常，无数据加载
  停顿迹象（弱证据）。
- **分支定位**：坍塌关联窗口内 `loss_ce_interm`（encoder proposal 分类，离 SCDA payload 最近的分支）
  全程平稳（0.4–0.6），爆炸的是 `loss_ce`（解码器最终分类）且 +DCNv4 的持续区间里 `loss_ce_dn`
  同步爆炸（2.44/2.00/1.73——连去噪查询都分错，说明是解码器整体状态扰动而非匹配局部抖动）。
  Clean A（无 SCDA）的尖峰形态相同。**尖峰是原生训练动力学现象，SCDA 不是制造者**；但 SCDA 变体
  run 的坍塌频率（5 次/8 run） vs 原生（0/1）样本过小，是否放大后果未定。
- **梯度范数未记录** → 无法进一步区分"单个坏 batch 冲击"与"累积漂移"，这是现有产物下机制归因的硬缺口。

## 3. 与稳定 run 的关键对照：损失尖峰本身不是坍塌的充分条件

F-Reg-Quality s42 在 iter 1679–1699 也出现过**同量级** ce 尖峰（2.136/0.812），但未发生任何
≥20 点 AP 坍塌。说明：这类瞬态损失尖峰是 SCDA 辅助回归管线的**反复出现的固有现象**；某次尖峰是否
演变为"恰好横跨评估点的坍塌"，取决于 20-iter 日志无法分辨的更细粒度因素（精确时序、权重偏移幅度与恢复速度）。
坍塌频率（按评估点计）：+DCNv4 1/20、Box-Gated 2/20、F-Reg-Quality 0/40（两 seed）、Q-BoxOnly 0/20、
Clean A 0/20——样本过小，不对"谁更易失稳"下机制结论，但"F-Reg-Quality 两 seed 零坍塌"作为
评估粒度的事实成立。

## 4. 明确记录的证据缺口

1. **坍塌点权重无法复评**：`checkpoint_keep=2` 只保留最后两个周期权重（5224/5499）与 best@5500；
   iter 1924/2199/2749 的权重已被轮换清理。按要求如实记录：**坍塌点/相邻权重复评不可行，未验证。**
2. 未记录逐 iter 梯度范数与逐 iter 损失 → 无法定位扰动发生的精确 iter 与来源分支。
3. **Box-Gated 的 proposal 选择质量无法从现有产物回答**：校准 JSON 的观察行只含计数（full/mask/box 按
   ρ 网格的逐层计数），不含被选 proposal 的 IoU/位置分布。已有证据只能说明**总量匹配 ≠ 组成匹配**：
   逐层池相对差 [-13.1%, −5.1%, −4.8%, +0.9%]（`diagnostics/gate_pool_composition.json`）——box 门在
   第一层比 mask 门少 13% 候选、最后一层多 0.9%，即两门控选择的位置与尺度组成确实不同。要回答
   "box 门是否排除了高价值边界 proposal"，需要一个有界诊断前向（加载两 run 的 best 权重，对同一批
   训练图分别记录两门控的选中 proposal IoU/尺度分布；无训练、预计 <10 分钟 GPU），本轮未执行，待授权。

## 5. 结论

- **判定：三处均为真实的训练瞬态失稳（权重劣化后自行恢复），非评估异常。** 评估链已被 6 次逐位复评
  排除；2/3 个坍塌点在评估前有明确损失扰动，第 3 个（2199）与记录时序及事后损失抬升自洽。
- **已报告的最终数字可信**：两组 best 都落在 5500（坍塌后早已恢复），best_val_ap 选择有效；
  64.738 / 63.231 是各自训练过程的确定性、可复现结果。
- **但结果解读需限定**（原报告结论已同步修订）：
  - Box-Gated 的 63.231 是"该 seed 下、经历了 2 次坍塌的训练过程"的结果；坍塌本身压低了轨迹与 best，
    因此 63.231 vs 66.143 的差距**不能全部归因于门控几何**。
  - 即便不计坍塌，数量校准只匹配了总量，未控制层级组成（逐层差至 −13%）与 proposal 质量——
    "mask 形状先验更有价值"仍是**未经分离的假设**，现有证据只支持"seed42 下 mask 门优于该全局
    数量校准的 box 门"。
- 对 +DCNv4：本轮"无收益"的结论维持；其训练动力学确实更差（1 次坍塌 + 2079–2139 约 120 iter 的
  ce 持续抬升），但**无法区分是 DCNv4 自身还是它与 SCDA 的交互**——当前协议的 DCNv4-only 是
  区分两者的正确下一步（待授权，本轮未启动）。

## 6. 重跑判定与最小后续（均待授权，本轮未执行）

- **不建议以"修复坍塌"为由重跑**：best 选择机制已使坍塌不影响最终数字；重跑不可能改变 64.738/63.231
  作为"该过程结果"的地位。
- 若要弄清 Box-Gated 的真实上限（排除坍塌干扰）或机制，按信息量/成本排序：
  1. 有界诊断前向：两门控选中 proposal 的 IoU/尺度分布对比（无训练，~10 分钟）——直接回答
     "收缩框是否排除高价值 proposal"，也为 Box-Gated 的"失败几何对照"定位提供证据；
  2. 训练时逐 iter 梯度范数/损失日志 + 观察下一次坍塌（需一次新训练，成本高）；
  3. Box-Gated 换 seed 重跑（回答"63.231 是否被坍塌压低"，但回答不了机制）。
- F-Reg-Quality 的"稳定"是评估粒度事实（两 seed 零坍塌）；其内部同样出现同量级损失尖峰这一事实
  提示：把资源投在理解/强化该稳定机制上，比叠加新模块更有依据。
