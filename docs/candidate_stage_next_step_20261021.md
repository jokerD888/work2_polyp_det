### 实际应记录的阶段比网页端多一个Mask-to-Box环节

已核对固定原生commit `3831d8514a3728535ace8d4ecc7d28044c42dd14`：当前YAML启用 `TWO_STAGE=True`、`INITIAL_PRED=True`、`INITIALIZE_BOX_TYPE='mask2box'`，9个普通Decoder层。

| 阶段 | 记录对象 | 区分的问题 |
|---|---|---|
| ① Encoder密集预测 | 合法proposal对应的原生类别分数与回归框、网格层级 | 密集池是否有满足给定IoU的框/病灶支持 |
| ② 原生Top300选中框 | 真实TopK索引与原生encoder预测框 | 固定密集候选池中的选择覆盖差额 |
| ③ 实际Decoder初始化 | 预测Mask经mask2box替换后的真实refpoint框、空/退化Mask统计 | 初始化转换是否改变目标覆盖 |
| ④ 每层普通Decoder预测 | 原生aux_outputs按层顺序的真实预测框、最终300 | 迭代中何时改善、停滞或退化 |
| ⑤ 原生Top100输出 | 原框、原分类分数与Mask融合分数 | 最终筛选/排序的影响 |

不能把 `interm_outputs.pred_boxes` 当成实际初始化：原生先保存该encoder框，随后会用预测Mask生成新refpoint。也不能把Decoder内部采样reference points一概当成实际输出框；最终以原生pred_box/aux_outputs结果为准。

原生代码位置：`maskdino_decoder.py:401`起构建密集预测和TopK；`:424`附近执行初始化Mask-to-Box；Decoder各层有reference detach。离散索引没有通常意义的排序梯度，但候选分数/共享特征可受额外目标影响；这些都需要实际路径验证，而非从detach推断“完全不可学习”。

### 输出和验收

- 各阶段统一到同一原图坐标系；合法性、padding、无限proposal和退化框单独记录。
- IoU=.5/.75/.9的一对一最大基数覆盖；逐GT“是否存在阈值候选”另报，不能混称严格召回。
- 同一模型内保持Query身份追踪，比较同一Query初始化到后续层的变化；A/B按GT对齐，不能把两模型相同数字的Query ID当成对应目标。
- 阶段转移同时报告出现/消失。不要因最大匹配的一次任意GT分配发生变化，就称某GT候选被破坏；也不把不同池规模的覆盖差唯一归因为特征。
- 全部最终框、分数、Query ID与既有原生预测/只读重放核对。模型只接收图像，eval/no_grad，无优化器或参数更新，不把GT送进前向。
- 输出原始阶段框与汇总，按中心/面积/单多框展示；不保存海量全分辨率Mask或跨图滞留GPU张量。

这次追踪是决定下一步挂载位置的有限检查，不安排阈值网格，不要求按人为比例发现某类问题。

共880张、941个GT；45张多框图像中有106个GT，约占全部GT的11.3%。多目标监督并非没有，但这个计数不能证明有106个可靠独立实例Mask。

按PolypGen面积最低四分位的相对面积阈值3.455%作跨域描述，Kvasir训练GT只有82/941（约8.7%）低于该值；Kvasir自身相对面积四分位为7.546%。这不是COCO小目标定义，也不用于拟合训练超参数。源域的尺度/多目标分布与主评估不同，需要限制泛化主张。

后续同一次工程验收还须审计：原始语义Mask及现有实例适配来源；哪些前景有唯一Box空间归属、哪些有重叠歧义；固定LSJ重放后GT/Mask/有效像素是否保留；各实际特征层的可用前景/局部背景与缺额。原始计数不是LSJ后计数，唯一Box空间归属也不是已经确认的像素级实例身份。

多框背景必须排除其他GT前景；语义Mask不能强拆实例。若可靠性规则使小/多目标几乎都没有辅助监督，就应缩小方法主张或改变方案，而不能用“实例均衡”掩盖监督缺失。也不按当前低分把困难样本排除。

## 诊断后采用分支决策

| 观察结果 | 下一步 |
|---|---|
| 密集池缺少合格框/可用病灶支持 | 检查特征尺度、空间支持和定位表征；局部关系只是待验证候选，不能认定对比loss必然解决 |
| 密集池有、Top300选择后丢失较多 | 优先设计直接关联原生选择分数与共享特征的局部关系监督 |
| 选中encoder框尚可，Mask-to-Box后明显退化 | 优先研究初始化转换及其空间支持，不预先增加Encoder对比 |
| 实际初始化尚可，Decoder后覆盖下降/改善不足 | 改研究Decoder定位/交互或合适的监督位置；不锁定Encoder方案 |
| 没有清楚的共同模式 | 暂不实现完整新模块，不强行从几个方向中选一个 |

这些是观察性机制定位，不是唯一的因果分解。尤其“早期池中没有IoU≥.5框”不等于表征不判别，因为早期候选的尺度/优化阶段本来不同。

## 方法规格与训练顺序

阶段与标签支持明确后，才冻结局部前景/背景构造、实例资格、挂载张量、损失公式、stopgrad和实际梯度通路。普通InfoNCE、实例均衡、尺度友好筛选本身均不能笼统称首次；独立价值必须针对最近邻方法解释。

先在Baseline上比较普通局部FG/BG对比与候选关联监督。在同协议对照下后者有值得继续的独立信号，再训练MSSL V1组合。若声称精细Mask具有独特价值，补同结构、同候选路径的Box信息对照，明确全局Mask统计校准仍属于使用Mask。若要分别声称均衡、局部性或可靠性贡献，须有各自匹配消融，不能仅凭五组矩阵归因。

已有A/B只有在训练机环境、数据、输入尺寸、微批量/累积、预算与初始化身份相符时才能复用；旧512/100epoch/SCDA或跨环境不一致的A/B不能当严格配对基线。Git同步观察器和协议，不会同步被忽略的权重/数据；需另行提供同协议权重或重建远端A/B。
